## 分隔符任务定义规范

在 `interface.json` 文件中，分隔符任务通过特定的 JSON 结构进行定义。这些任务的 `name` 字段包含长破折号（如"——— 可连续任务 ———"），用于在用户界面中作为视觉分隔符。每个分隔符任务具有以下关键属性：

- **name**: 任务的显示名称，包含长破折号，用于在任务列表中作为分组标题
- **label**: 任务的标签，通常与 `name` 相同或简化版本
- **entry**: 作为 UI 渲染标记，用于标识该任务为分隔符类型
- **description**: 指向 Markdown 文档的路径，提供分组说明信息
- **group**: 分隔符任务现在统一使用分组标识符，所有分隔符任务都属于 'others' 分组

在 `interface.json` 中，分隔符任务通过 `import` 数组进行导入，包括三种分隔符类型：
- `resource/tasks/separators/continuous_task.json`
- `resource/tasks/separators/independent_task.json`
- `resource/tasks/separators/new_task.json`

## 三种分隔符类型详解

### 可连续任务分隔符

可连续任务分隔符用于标识可以自动连续执行的任务组。这类任务的特点是开始界面与结束界面都为主界面，可以形成完整的自动化执行流程。

**任务定义示例**：
```json
{
    "name": " ——— 可连续任务 ———",
    "label": "——— 可连续任务 ———",
    "entry": "可连续任务分隔符",
    "description": "Resource/descs/others/continuous_task.md",
    "group": ["others"]
}
```

**使用场景**：
- 自动化日常任务流程
- 无需人工干预的连续执行
- 主界面间无缝衔接的任务组合

### 独立任务分隔符

独立任务分隔符用于标识无法与其他任务自动串联执行的任务组。这类任务通常需要手动触发，且开始或结束界面不是主界面。

**任务定义示例**：
```json
{
    "name": " ——— 独立任务 ———",
    "label": "——— 独立任务 ———",
    "entry": "独立任务分隔符",
    "description": "Resource/descs/others/independent_task.md",
    "group": ["others"]
}
```

**使用场景**：
- 特殊界面要求的任务
- 需要用户手动确认的任务
- 流程复杂的独立操作

### 新增任务分隔符

新增任务分隔符用于标识新添加但尚未配置的任务。这些任务会在系统更新后出现在列表末尾，需要用户手动调整到合适的分组中。

**任务定义示例**：
```json
{
    "name": " ——— 新增任务 ———",
    "label": "——— 新增任务 ———",
    "entry": "新增任务分隔符",
    "description": "Resource/descs/others/new_task.md",
    "group": ["others"]
}
```

**使用场景**：
- 系统更新后的任务迁移
- 临时存放新发现的任务
- 用户自定义任务的初始位置

## 新的分组系统与标识符

**更新** 分隔符任务现在使用统一的分组系统，所有分隔符任务都归类到 'others' 分组中，不再按照任务类型进行细分。

### 分组配置

在 `interface.json` 的 `group` 数组中，现在包含三个主要分组：

```json
"group": [
    {
        "name": "continuous",
        "label": "可连续任务/日常任务",
        "description": "在完成当前任务后，可以连续执行下一个任务",
        "default_expand": true
    },
    {
        "name": "independent", 
        "label": "独立任务/开荒任务",
        "description": "无法与其他任务自动串联执行",
        "default_expand": true
    },
    {
        "name": "others",
        "label": "其他",
        "description": "分割线等，一般无需添加",
        "default_expand": true
    }
]
```

### 分隔符任务的分组标识符

所有分隔符任务现在都使用相同的分组标识符：
- `group`: ["others"]

这种统一的分组策略简化了任务管理，使得分隔符任务可以在同一个分组中进行视觉分组，而不影响其在前端的渲染效果。

## UI渲染标记与分组说明

分隔符任务的 `entry` 字段（如"可连续任务分隔符"、"独立任务分隔符"、"新增任务分隔符"）在前端界面中作为 UI 渲染标记，用于标识该任务为分隔符类型。前端根据 `entry` 字段的值来决定如何渲染该任务，通常将其显示为一个分组标题。

`description` 字段指向的 Markdown 文档提供了分组说明信息。这些文档在前端界面中以富文本形式展示，为用户提供详细的分组说明。

### 可连续任务说明
可连续任务指在完成当前任务后，可以自动继续执行下一个任务的任务类型。这类任务通常具有以下特点：
1. **收尾相接**：开始界面与结束界面都为主界面
2. **流程连贯**：多个任务之间形成一个完整的执行流程，无需人工干预

### 独立任务说明
独立任务指无法与其他任务自动串联执行的任务类型。这类任务通常具有以下特点：
1. **界面独立**：开始界面或结束界面不是主界面，无法与其他日常任务自动衔接
2. **需手动触发**：通常需要用户手动选择执行，不建议加入自动化任务链中
3. **流程特殊**：任务执行流程较为特殊，需要特定的前置条件或后续处理

### 新增任务说明
当更新后有新增任务时，会添加在列表最后。使用时需要注意：
1. **任务位置调整**：需要根据任务类型手动调整其位置
2. **配置建议**：建议先进行单独测试，确认运行正常后再加入日常流程
3. **注意事项**：此分隔符后仅作为临时存放位置，不建议长期保留

## 前端渲染逻辑与设计原理

分隔符任务在前端渲染逻辑中不参与实际的执行流程，仅用于视觉分组和用户体验优化。其设计原理如下：

### 渲染机制
1. **非执行性**：分隔符任务的 `entry` 字段在任务执行流程中被识别为分隔符，不会触发任何实际的任务执行逻辑
2. **视觉分组**：前端根据 `entry` 字段的值将任务列表划分为不同的组，每个分隔符任务作为一组的标题
3. **用户体验优化**：通过分隔符任务，用户可以更清晰地理解任务列表的结构和分组，提高配置和管理任务的效率

### 提示信息配置
在 `分隔符.json` 文件中，分隔符任务的 `focus` 字段定义了在任务执行过程中显示的提示信息：

```json
{
    "可连续任务分隔符": {
        "focus": "—— 即将执行可连续任务！——"
    },
    "独立任务分隔符": {
        "focus": "—— 即将执行独立任务！——"
    },
    "新增任务分隔符": {
        "focus": "请手动调整新增任务至合适位置！"
    }
}
```

这些提示信息在任务执行过程中显示，帮助用户了解当前执行的任务组。

### 设计原则
1. **明确的视觉区分**：通过长破折号格式的名称和专门的分隔符类型，让用户能够快速识别不同类型的分组
2. **语义化的任务组织**：按照任务的执行特性进行分组，便于用户理解和配置
3. **渐进式任务管理**：从简单到复杂，从独立到连续的任务组织方式
4. **用户引导性**：通过描述文档和提示信息，指导用户正确配置和使用任务
