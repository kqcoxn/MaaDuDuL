## 简介

- agent 子进程执行配置（child_exec、child_args）的启动逻辑
- **新增** 模块化任务组织系统：通过import机制替代原有内联任务定义

- **新增** 按功能分类的任务文件结构：daily、single、separators等类别
- **新增** 每日采购任务的复杂选项配置：支持多种采购模式和子选项
- **新增** 采购模式选项配置：支持"逐个购买"和"一键购买"两种模式

### Agent 子进程执行（agent）
- child_exec：子进程可执行文件路径（系统路径），CWD 为 interface.json 所在目录

## 模块化任务组织系统

### 任务文件分类结构
系统采用模块化设计，将不同类型的任务分离到独立的JSON文件中：

- **daily 目录**：日常重复性任务
  - illustrate（说明）、guide（操作指南）、start_game（启动游戏）、claim_mail（领取邮件）、leaf_change（叶子互换）、claim_candy（领取糖果）、purchase（每日采购）等
  - 支持周期性检查和复杂选项配置
- **single 目录**：单次执行任务
  - quick_plot（快速剧情）、continuous_battle（连续作战）、level_rewards（领取关卡奖励）等
- **separators 目录**：任务分隔符
  - continuous_task（可连续任务分隔符）、independent_task（独立任务分隔符）、new_task（新增任务分隔符）
- **说明与指南**：独立的任务说明和操作指南（英文命名）

### 任务文件结构模式
每个任务文件都遵循相同的结构模式：

```json
{
  "task": [
    {
      "name": "任务名称",
      "label": "显示标签",
      "entry": "pipeline入口节点",
      "default_check": true/false,
      "description": "说明文档路径",
      "option": ["选项键1", "选项键2"]
    }
  ],
  "option": {
    "选项键": {
      "type": "switch/select",
      "label": "选项标签",
      "cases": [
        {
          "name": "Yes/No/具体值",
          "option": ["嵌套选项"],
          "pipeline_override": {"节点名": {"next/action": "值"}}
        }
      ]
    }
  }
}
```

## import机制详解

### import 数组的工作原理
import 数组替代了原有的内联任务定义，通过文件路径动态加载任务配置：

```json

  "resource/tasks/separators/new_task.json"

```

### 导入机制的优势
- **模块化管理**：按功能分类的任务文件便于维护和扩展
- **独立开发**：不同任务可以独立开发和测试
- **版本控制**：单个任务的修改不会影响其他任务
- **性能优化**：只加载需要的任务文件，减少内存占用
- **可扩展性**：新增任务只需添加新的JSON文件和import路径
- **国际化支持**：英文命名的任务文件符合国际化的标准

### 任务合并过程
1. 系统读取 import 数组中的所有文件路径
2. 逐个加载每个任务文件
3. 提取每个文件中的 task 数组和 option 对象
4. 合并所有任务定义到最终的任务列表中
5. 合并所有选项定义到最终的选项系统中

```mermaid

B --> C["加载 JSON 文件"]
C --> D["提取 task 数组"]
C --> E["提取 option 对象"]
D --> F["合并到任务列表"]
E --> G["合并到选项系统"]
F --> H["最终任务定义"]
G --> H
```

## 故障排查指南
- 控制器连接失败
  - 检查 Adb/Win32/PlayCover 的 type 与参数配置是否正确
  - PlayCover：确认 uuid 与 PlayTools 服务地址匹配，且目标应用已在 PlayCover 中启用 MaaTools
- 资源加载异常
  - 确认 resource.path 的相对路径正确，且资源目录包含 pipeline、image、model 等必要文件
  - 如需按控制器过滤，确保 controller.name 与 resource.controller[] 匹配
- Agent 启动失败
  - 检查 child_exec 是否为系统可执行文件路径，child_args 是否正确传递
  - 确认 CWD 为 interface.json 所在目录，且 agent/main.py 可正常导入依赖
- **新增** import 机制故障
  - 检查 import 数组中的文件路径是否正确
  - 确认被导入的任务文件格式正确，包含有效的 task 和 option 结构
  - 验证任务文件的 JSON 语法，确保无语法错误
  - 确认任务文件使用英文命名（如 illustrate.json 而非 说明.json）
- **新增** 模块化任务系统故障
  - 检查任务文件是否位于正确的目录结构中
  - 确认任务文件的命名规范，避免特殊字符和空格
  - 验证任务文件中的 entry 节点是否与对应的 pipeline 节点匹配
  - 确认英文命名的任务文件路径与 import 数组中的路径一致
- **新增** 英文命名任务文件故障
  - 检查任务文件是否为正确的英文命名（如 illustrate.json、guide.json）
  - 确认文件路径大小写与 import 数组中的路径完全一致
  - 验证任务文件内容结构符合标准格式
- **新增** 复杂选项系统故障
  - 检查选项定义的语法结构，确保 type、label、cases 等字段完整
  - 确认 pipeline_override 的语法正确，节点名称与实际 pipeline 节点一致
  - 验证嵌套选项的引用关系，避免循环引用
- **新增** 数据统计上报失败
  - 检查网络连接是否正常
  - 确认统计服务器地址 http://ts.codax.site/repo 可访问
  - 查看请求超时设置（3秒）是否过短
- **新增** 包管理器配置错误
  - 检查 maa_pi_config.json 中的资源包名称是否正确
  - 确认对应资源包目录存在且包含必要文件

## 结论
interface.json 通过标准化的字段与结构，将控制器、资源、任务、选项、Agent 子进程和统计数据上报模块有机整合，形成可配置、可扩展、可维护的自动化执行体系。随着 v0.2.0 版本的重大更新，系统完成了从单个interface.json到模块化JSON任务组织系统的迁移，通过import机制实现了任务文件的模块化管理。新增的复杂选项系统、详细的说明文档、数据统计上报、包管理器配置和采购模式选项进一步增强了系统的完整性和用户体验。

**重要更新**：本次更新实现了任务配置文件的英文命名标准化，所有JSON任务配置文件从中文命名（如 说明.json、操作指南.json）改为英文命名（如 illustrate.json、guide.json），同时更新了interface.json中的import数组以反映新的文件名。这一国际化改进保持了原有功能的完整性，同时提升了系统的全球可用性。新增的"每日采购-日常商店-采购模式"选择框提供了灵活的购买策略，支持"逐个购买"和"一键购买"两种模式，满足不同用户的操作习惯。遵循 V2 协议规范，合理配置控制器参数、资源路径、Agent 启动参数、统计上报配置、模块化任务系统和采购模式选项，可有效提升任务执行的稳定性与可移植性。
