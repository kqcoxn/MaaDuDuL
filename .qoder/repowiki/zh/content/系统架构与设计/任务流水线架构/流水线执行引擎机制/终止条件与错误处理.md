## 简介

本文档深入分析MaaDuDuL项目中任务流程的终止条件与错误处理机制。重点涵盖以下方面：

- **终止条件判断逻辑**：当前节点next列表为空或所有后继节点持续检测失败直至超时的具体判断机制
- **on_error错误处理跳转机制**：识别超时或动作执行失败后的节点跳转流程
- **JumpBack回跳机制**：基于回调协议的节点回跳控制技术实现
- **pipeline_override注入实现**：on_error链式处理和运行监测器注入的技术细节
- **奖励收集系统专门处理策略**：针对任务奖励和通行证奖励的特殊处理逻辑
- **Tasker类的pipeline_override机制**：如何为所有节点自动注入运行监测器

### on_error错误处理跳转机制

#### 错误处理链式处理

系统实现了完整的on_error链式处理机制：

```mermaid
sequenceDiagram
participant Node as 当前节点
participant ErrorHandler as 错误处理器
participant NextNode as 下一个节点
participant Monitor as 监测器
participant Callback as 回调协议
Node->>ErrorHandler : 发生错误
ErrorHandler->>Monitor : 检查停止状态
Monitor-->>ErrorHandler : 返回停止状态
alt 任务未停止
ErrorHandler->>NextNode : 跳转到on_error节点
NextNode->>NextNode : 执行错误处理逻辑
NextNode->>Monitor : 检查停止状态
Monitor-->>NextNode : 返回停止状态
alt 任务未停止
NextNode->>Callback : 发送JumpBack信号
Callback-->>NextNode : 接收回跳控制
alt 允许回跳
NextNode->>NextNode : 执行回跳操作
else 禁止回跳
NextNode->>NextNode : 继续执行错误处理
end
else 任务停止
NextNode->>ErrorHandler : 请求停止
ErrorHandler->>ErrorHandler : 终止执行
end
else 任务停止
ErrorHandler->>ErrorHandler : 终止执行
end
```

#### 节点跳转流程

**错误处理跳转的具体步骤**：

1. **错误检测**：当前节点执行失败或超时
2. **on_error检查**：读取节点的on_error配置
3. **监测器注入**：确保on_error链路也包含监测器
4. **链式执行**：按照on_error列表顺序执行错误处理节点
5. **状态检查**：每步执行后检查任务停止状态
6. **JumpBack控制**：根据回调协议控制回跳行为
7. **最终决策**：根据执行结果决定是否继续或终止

### JumpBack回跳机制

#### 回跳控制协议

系统基于MaaFramework回调协议实现了完整的JumpBack回跳控制机制：

**回调协议结构**：
```json
{
    "task_id": 12345,
    "name": "NodeA",
    "list": [
        {
            "name": "NodeB",
            "jump_back": false,
            "anchor": false
        },
        {
            "name": "NodeC", 
            "jump_back": true,
            "anchor": false
        },
        {
            "name": "LastHandler",
            "jump_back": false,
            "anchor": true
        }
    ],
    "focus": any
}
```

**回跳控制逻辑**：
- `jump_back: true` - 允许回跳到前一个节点
- `jump_back: false` - 禁止回跳，继续正常执行
- `anchor: true` - 锚点引用，指向特定的节点名称

**更新** 完整实现了基于回调协议的JumpBack回跳控制机制。

**章节来源**
- [2.3-回调协议.md](file://instructions/maafw-guide/2.3-回调协议.md#L133-L166)

```mermaid
flowchart TD
ErrorDetected[错误检测] --> CheckJumpBack{检查JumpBack状态}
CheckJumpBack --> |允许回跳| ExecuteJumpBack[执行回跳操作]

UpdateState --> ResumeExecution[恢复执行]

NextNode --> CheckState{检查任务状态}
CheckState --> |正常| ContinueError

ResumeExecution --> CheckState
```

## 性能考量

### 监测器开销控制

系统通过以下方式控制监测器的性能开销：

1. **最小化检测频率**：监测器只在关键节点执行
2. **快速返回机制**：停止状态检测快速返回
3. **避免重复注入**：防止重复注入监测器造成性能损失
4. **JumpBack状态缓存**：减少回跳状态检查的计算开销

**更新** 新增了JumpBack状态缓存机制，进一步优化了性能表现。

### 内存管理

- **及时释放资源**：任务结束后自动清理相关资源
- **避免内存泄漏**：确保所有回调函数正确释放
- **优化数据结构**：使用高效的数据结构存储节点信息
- **回跳状态管理**：合理管理JumpBack相关的状态信息

**更新** 新增了回跳状态管理机制，确保状态信息的有效管理。

## 故障排除指南

### 常见问题及解决方案
